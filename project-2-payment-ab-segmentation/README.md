# Проект 2: A/B-тест оплаты и сегментация клиентов

Финальный проект Karpov.Courses, вариант 2.

Проект состоит из трёх частей:

1. анализ A/B-теста новой механики оплаты;
2. SQL-сегментация клиентов для персонализированного маркетинга;
3. пересчёт продуктовых метрик после получения дополнительного файла с
   назначениями групп.

## Главный вывод A/B-теста

Новую механику пока не рекомендуется раскатывать на всех пользователей.

| Метрика | Группа A | Группа B | Разница B − A | p-value |
|---|---:|---:|---:|---:|
| CR | 5.07% | 4.62% | −0.456 п.п. | 0.445 |
| ARPU | 47.35 | 58.06 | +10.71 | 0.198 |
| ARPPU | 933.59 | 1 257.88 | +324.29 | 0.005 |

Статистически значимо вырос только `ARPPU`. При этом:

- рост `ARPU` не подтверждён;
- конверсия в оплату не улучшилась;
- 128 из 314 плательщиков B совершили платёж около 1900, тогда как в A таких
  платежей нет;
- 149 оплативших пользователей отсутствуют в таблице активности.

Поэтому перед полной раскаткой необходимо проверить источник пика 1900,
корректность логирования активности и продолжить эксперимент с заранее
выбранным основным KPI.

## Ноутбуки

### Простая версия

[Открыть `project_2_simple.ipynb`](notebooks/project_2_simple.ipynb)

Учебная версия с прямой последовательностью расчётов. В кодовых ячейках нет
собственных функций, `for` и `while`.

### Полная версия

[Открыть `project_2_full.ipynb`](notebooks/project_2_full.ipynb)

Основной анализ остаётся линейным. В конце находятся только две функции:

- `recalculate_metrics()` — загружает `groups_add`, добавляет пользователей и
  пересчитывает метрики;
- `plot_metrics()` — строит три графика без цикла.

Внутри используются обычные операции `read_csv`, `concat`, `merge` и `groupby`.
Это формальное требование третьей части задания в понятной реализации уровня
junior/junior+.

## SQL

[Открыть запрос сегментации](sql/customer_segmentation.sql)

Источник данных в Redash: **StartDA (lab)**.

Запрос возвращает для каждого из 10 000 клиентов:

- `customer_id`;
- `customer_city`;
- `registration_date`;
- `days_since_registration`;
- `orders_count`;
- `purchase_events_count`;
- `avg_delivery_days`;
- `segment`.

Предварительная агрегация заказов и событий защищает расчёты от many-to-many
размножения строк.

## Запуск

Из корня этого проекта:

```bash
python -m pip install -r requirements.txt
jupyter notebook
```

Откройте папку `notebooks` и выполните `Run All`. Оба ноутбука используют
относительный путь `../data/raw`, поэтому работают после обычного клонирования.
