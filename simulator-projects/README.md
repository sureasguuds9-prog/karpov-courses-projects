# Карпов Курсы — проекты симулятора

Эта папка — единая подборка учебных проектов по симулятору Karpov Courses. Исходные проекты не перемещались и не удалялись: здесь находятся удобные копии без виртуальных окружений, кэшей и временных файлов.

## С чего начать

1. Для автоматизации и отчётности откройте `01_Airflow_Telegram`.
2. Для статистики и экспериментов откройте `02_AB_тесты`.
3. Для анализа флешмоба и прогнозирования откройте `03_Флешмоб_и_прогнозирование`.
4. Для большого SQL-проекта по сервису доставки откройте `04_SQL_аналитика_доставки`.

## 01_Airflow_Telegram

- `yaroslav_zinchenko_feed_report.py` — ежедневный Telegram-отчёт по ленте: DAU, просмотры, лайки, CTR и графики за 7 дней.
- `yaroslav_zinchenko_app_report.py` — отчёт по всему приложению: общая аудитория без двойного подсчёта, лента, мессенджер, пересечение продуктов, бизнес-сигналы, PNG и CSV.
- `yaroslav_zinchenko_daily_etl.py` — ежедневный ETL ленты и мессенджера с агрегациями по полу, возрасту и операционной системе.

Основные файлы:

- [Отчёт по ленте](01_Airflow_Telegram/yaroslav_zinchenko_feed_report.py)
- [Отчёт по всему приложению](01_Airflow_Telegram/yaroslav_zinchenko_app_report.py)
- [Ежедневный ETL](01_Airflow_Telegram/yaroslav_zinchenko_daily_etl.py)

## 02_AB_тесты

- `aa_test_task_1.ipynb` — A/A-проверка системы сплитования.
- `lesson-4-ab-tests/notebooks/ab_test_groups_1_2.ipynb` — A/B-тест на данных актуального потока симулятора.

## 03_Флешмоб_и_прогнозирование

- `notebooks/flashmob_causal_impact.ipynb` — оценка эффекта флешмоба.
- `notebooks/flashmob_causal_impact_explained.ipynb` — версия с подробными пояснениями.
- `notebooks/user_activity_forecast_orbit.ipynb` — прогноз пользовательской активности.
- `sql/flashmob_daily_metrics.sql` — подготовка дневных метрик.
- `data/flashmob_daily_metrics.csv` — сохранённая выгрузка метрик.

## 04_SQL_аналитика_доставки

Полный SQL-проект по данным симулятора доставки: качество данных, заказы, выручка, unit-экономика, воронка, retention, когорты, маркетинг, курьеры, ассортимент, пиковые часы и сегменты пользователей. Начинать с `README.md` или `all_queries.sql`.

## Важно

- Папка является удобной подборкой учебных материалов. Исходные проекты сохранены отдельно и не изменялись.
- Токен Telegram не хранится в коде: DAG получает его из переменной окружения `REPORT_BOT_TOKEN`.
- Технические окружения `.venv`, `.forecast-venv`, кэши Python и история Git намеренно не копировались.
