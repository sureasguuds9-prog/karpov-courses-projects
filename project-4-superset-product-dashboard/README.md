# Продуктовый дашборд ленты и мессенджера

Учебный BI-проект Karpov.Courses для мониторинга продуктового состояния ленты новостей и сервиса сообщений.

[Открыть дашборд в Apache Superset](https://superset.lab.karpov.courses/superset/dashboard/8835/)

> Для просмотра может потребоваться авторизация на учебной платформе.

## Краткий результат

Собран единый дашборд из шести визуализаций и фильтра периода. Он позволяет сравнивать дневную активную аудиторию сервисов, оценивать переход пользователей из ленты в сообщения и анализировать общий объём сообщений по полу и возрастным группам.

## Аналитические вопросы

- Как меняется DAU ленты и мессенджера?
- Какая доля пользователей ленты также отправляет сообщения?
- Какие группы формируют больший объём переписки?
- Как показатели меняются за выбранный период?

## Состав дашборда

| Блок | Что показывает |
|---|---|
| DAU сервисов | Уникальных активных пользователей каждого сервиса по дням |
| Пересечение сервисов | Долю пользователей ленты, которые также отправляли сообщения |
| Сообщения по полу | Общее число отправленных сообщений по полу отправителя |
| Сообщения по возрасту | Общее число сообщений в шести возрастных группах |
| Период анализа | Фильтр Superset, связанный со всеми графиками |

Возрастные группы: `до 18`, `18–24`, `25–34`, `35–44`, `45–54`, `55+`.

## Логика метрик

- **DAU** — число уникальных пользователей с хотя бы одним действием в сервисе за день.
- **Сообщения по полу и возрасту** — число событий отправки, а не число пользователей.
- **Доля пользователей ленты в мессенджере** рассчитывается на сопоставимом временном интервале; знаменатель — активные пользователи ленты.

Объём сообщений нельзя автоматически интерпретировать как интенсивность общения одного пользователя: крупная группа может давать больше сообщений только из-за размера. Для сравнения интенсивности нужна метрика «сообщений на активного отправителя».

## Ограничения

- последняя дата учебной таблицы может быть неполной;
- дашборд описывает динамику, но не устанавливает причины изменений;
- для операционного мониторинга дополнительно нужны целевые уровни и пороги предупреждений.
